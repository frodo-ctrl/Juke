白底黑字的 J，能长出几种符号

五版方向，全部以可读的艺术字 J 为基础，只用纯黑与纯白。每一版都押在一个不同的产品语义上：胶片、点唱机、追剧进度、一笔连续、负形双关。重点不是谁更花哨，而是缩到 16px 还认不认得出 J。

产品事实

Juke（剧刻）是剧集追踪与推荐 App，标语「好剧 从此刻开始」。核心动作是记录看到哪一集，不是播放器本身。

现有符号缺口

启动页用的是斜体衬线「Juke」，J 至今只是字母，没有独立符号。现网 launcher 图标是一块 slate 蓝灰场记板加两侧金黄胶片点。

可沿用的基因

Work Sans 全字重、衬线斜体的品牌腔调、胶片齿孔与唱盘母题、金黄 #FEBD0A 与蓝灰 #324E5B 的既有资产。

本轮约束

白底黑字，不加渐变与外发光；J 必须读得出来；不做抽象到认不出字母的方向。彩色点缀仅在 E 版作为可选试点出镜。

A

衬线刻痕

editorial notch

把启动页那套 衬线斜体的品牌腔调 直接搬进图标：细竖笔、粗底钩，高笔画对比做出「 editorial / 杂志感」。创新点在钩部——厚笔画里挖出三个胶片齿孔，让一个衬线 J 同时是一段胶片。

高对比衬线笔画（细 10u / 粗 20u）＋ 厚钩内负形齿孔，把「字母」和「胶片」压在同一轮廓里。

B

点唱盘

jukebox dial

回到词源：juke = jukebox。竖笔是唱臂，底钩换成一张同心圆唱片，圆心一刀斜切就是落下的唱针。J 的识别靠「上竖下圆」的结构关系，而不靠笔画细节。

创新点
把唱片做成可拆解的图形库：外环、沟槽、轴心三层，之后加载态可以直接让它转起来（旋转即播放）。

C

进度刻度

progress j 产品语义最强

这一版不押字体、押行为：竖笔被切成三段，就是「看到第几集」的进度格；底钩保持实心厚弧，负责在任何尺寸下把 J 认出来。它同时是字母、也是状态条。

创新点
段数可以真的变成进度：三段的缺口令它成为唯一一版「能随产品状态变化」的图标（追完 → 合并为实心 J）。

D

一笔闭环

single stroke 小尺寸最稳

一笔不断写成的 J：顶部横杠折进竖笔，竖笔相切地滑进底钩，钩尾再向上回挑一个 200° 的大弧。所有转折共享同一个半径，圆头收笔，几何上几乎无可挑剔。

创新点
钩尾上挑回勾是记忆点：普通 J 到 180° 就停，它多走 20°，形成「回弹」的动势，也暗示下一集。
品牌契合
与 Work Sans 的几何中性最搭，做 UI 内联图标、单色 monochrome 层、印刷都零成本。
风险
性格偏冷静、偏工具，情绪温度低于 A / B；回勾在 16px 会和主钩并成一团（见下方光学修正版）。

E

负形双关

negative space v2 · 已去黑底板

把「挖」的方向掉个头：不再铺黑底板，而是让 J 的底钩往上回挑、自己围出一间白腔，腔里放一枚实心黑三角。一眼是 J，再看是「J 里在播放」——三层黑白关系全部留在白底上，不再需要任何底色块。

创新点
负形全部由 J 自己生成：底钩回挑围出一间白腔，白腔里再放黑三角，三层黑白、零底色块。它是五版里唯一「图形内部自带留白结构」的，放大到海报、缩小到水印都不需要背景配合。
品牌契合
那间白腔天然是一个容器：之后可以往里换内容——正在追的集数、播放状态、甚至一帧剧照，图标本身就能变成状态载体。
风险
回挑让 J 有被读成 U 的可能，目前靠顶部横杠拉回来；三角在 16px 只剩约 2px，双关会消失，退化成一只普通 J（字母识别本身不受影响）。

C · 进度刻度 J

recommend for launcher · 512 / adaptive foreground
  1. 语义独占。A、B、D 别人也在做；「J 的竖笔＝已看进度」只有追剧产品能用，它把图标和核心功能绑在一起，而不是装饰。
  2. 结构最抗缩放。实心厚底钩 R18 / 16u 承担识别度，刻度只作用在竖笔上——即使刻度被吃掉，剩下仍然是一个干净的 J。
  3. 有成长空间。后续可以做「本周追完 → 刻度合并」的状态变体，也能和现有金黄圆点资产无缝衔接。
如果你更想要温度而不是差异化：选 D（一笔闭环）作为系统级图标语言，它的中性气质最适合内嵌到 UI 里当品牌小图标；把 C 只用在 launcher 一处。

E 已按你的要求去掉黑底板，现在是纯白底＋黑 J＋黑三角，完全合规。但它的记忆点集中在三角上，16px 时双关会消失，所以更适合当 App 内的品牌位、启动图与水印，而不是主 launcher 图标。

落地规范

若选中的方案要交给开发，跟着这组数字走

画布与安全区

矢量按 120×120u 绘制，图形锁在 20–100u（66.7%）内。Android adaptive icon 前景层是 108dp、可视安全区 66dp——照这个比例出图，套上任何系统蒙版都不会被切。

笔画基准

主笔画 13–16% 字高（本板 C/D 用 16u、A 粗笔 20u）。低于 8% 在 16px 下会断墨；细笔画只允许出现在 ≥64px 的场合。

圆角策略

图标容器不画死圆角，交给系统蒙版；图形自身的圆角统一 R17–20，与 App 内 16/24dp 的 Shape 阶梯对得上，不会出现「图标一套语言、界面另一套」。

响应式图标

正式方案建议出 两个光学尺寸：完整版（≥40px）与修正版（≤32px）。这是 iOS/Android 系统图标通行的做法，不是妥协。

Monochrome 层

D 与 C 可直接复用为 ic_launcher_monochrome，无需重画。A 的齿孔与 E 的三角属于第二层信息，单色主题下建议各自简化为单层。

背景层待办

现网背景层仍是 Android Studio 默认绿 #3DDC84。白底黑字的方向要求背景层同步改为纯白，否则深色主题下图标四周会出现一圈绿边。

不做的尝试

已排除 · 附原因
rejected 01花体装饰 J

纯手写连笔的 J 在大图很好看，但笔画粗细不可控、16px 下必糊，且无法矢量化成稳定源文件。只在 A 版里借了它「对比」的一个切面。

rejected 02渐变 / 3D 立体 J

与「白底黑字」直接冲突；立体高光在 16px 会退化成脏灰，也不利于单色主题与印刷墨稿。

rejected 03中文「剧」为主图形

笔画密度太高，launcher 尺寸下糊成方块。更合适的用法是把「剧刻」留在启动页与字标里，图标层只承担字母。

rejected 04给现图标换配色

把场记板改成黑白是成本最低的方案，但它解决不了真正的问题：Juke 至今没有一个符号。本轮按「造符号」处理。
